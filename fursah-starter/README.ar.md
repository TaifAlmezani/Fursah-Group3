# فرصة — FURSAH

ابنِ تطبيقًا للبحث عن الفرص اعتمادًا على تصميمك في اليوم الأول والأطر والأدوات التي اخترتها في اليوم الثاني.

توفر ساعي **1,000 إعلان خام خيالي، وواجهة مكتملة، وهيكل API يعمل**. تتولى أنت تجهيز البيانات، والمخططات الداخلية، والتخزين، وعميل النموذج، والتعليمات الموجهة للنموذج، والاسترجاع، والأدوات، وتنسيق التنفيذ، وقواعد التطبيق. لا تعيد نسخة البداية توصيات وهمية.

## ما نقدمه وما تقرره أنت

| ما يوفره المشروع | قرارات المتدرب |
|---|---|
| الواجهة وصيغ طلبات واستجابات HTTP | السجلات الداخلية ومخطط قاعدة البيانات وتقنية التخزين |
| عناوين المسارات والأخطاء المنظمة | مزود النموذج والمصادقة والإطار أو SDK المباشر |
| تشغيل API والتحقق من الطلبات | التعليمات الموجهة للنموذج والاستخراج والاسترجاع |
| وقت تقييم موحد لكل طلب | الأدوات وتنسيق التنفيذ والترتيب وقواعد الأهلية |
| أدوات اختيارية لقراءة CSV وJSON | طريقة تخزين البيانات المجهزة والوصول إليها |

حافظ على توافق عقد API العام مع الواجهة. **هذا لا يفرض مخطط قاعدة بيانات أو تصميم وكيل محددًا.** يمكنك دمج ملفات المتدرب أو تقسيمها أو إعادة تسميتها أو استبدالها، مع تحديث الاستيراد ونقاط اتصال API.

## مسار العمل

| الخطوة | ماذا تفعل؟ | النتيجة التي تراها |
|---|---|---|
| 1. التشغيل | اتبع إعداد [الخادم](backend/README.ar.md) و[الواجهة](frontend/README.ar.md). | تظهر الواجهة ويعيد `/health` الرمز 200. البحث غير المكتمل متوقع. |
| 2. الفهم | اتبع [دليل البيانات](data/README.ar.md) والدفتر على عشرة إعلانات. | تستطيع شرح المصادر والمعلومات الناقصة والإعلانات المرتبطة. |
| 3. التجهيز والتخزين | أضف للعينة الحقائق التي يحتاجها تطبيقك واختر وسيلة التخزين. | تحتفظ السجلات المحفوظة بمعرفات المصادر والأدلة الأصلية. |
| 4. ربط التفاصيل | نفّذ الوصول إلى التخزين وحوّل سجلًا فعليًا إلى عقد التفاصيل. | يعيد `/api/v1/opportunities/{id}` هذا السجل. |
| 5. ربط البحث | استرجع المرشحين وتعامل مع القيود وأعد نتيجة مدعومة. | يعمل بحث فعلي من خلال الواجهة المقدمة. |
| 6. التوسّع | طبّق التجهيز على جميع الإعلانات الألف وراجع الحالات الصعبة. | يتعامل التطبيق مع المجهول والتحديثات والتعارضات. |

هذا ترتيب للتعلّم، وليس بنية إلزامية للوكيل. العينة الصغيرة مرحلة أولى وليست تقليلًا للمطلوب النهائي.

### ثبّت المكتبات في البيئة الصحيحة

- **الخادم:** ثبّت `backend/requirements.txt` في بيئة Python.
- **الدفتر:** اختر نواة Python المناسبة، وثبّت Jupyter عند الحاجة، واستخدم خلية المكتبات لتثبيت pandas وIPython.
- **الواجهة:** ثبّت Node.js مع npm، ثم نفّذ `npm ci` داخل `frontend/`.
- **تنفيذك:** أضف فقط مكتبات النموذج والتخزين وإطار العمل التي تختارها. تشغيل هيكل الخادم لا يثبّت إطار ذكاء اصطناعي ولا ينفذه.

### حجم العمل المتوقع

التمارين التسعة تعلّم تجهيز ملاحظات المصادر، ولا تكمل محرك البحث. أول إنجاز تطبيقي: تحويل نشاط واحد من العينة إلى استجابة تفاصيل فعلية، ثم بحث يعمل من الواجهة. بعد ذلك توسّع إلى جميع الإعلانات. استخدم [ورقة ربط الحقول](data/README.ar.md#mapping) قبل كتابة التنفيذ. لا يلزم ملء كل حقل اختياري لإكمال أول مسار يعمل.

│       └── infrastructure/

دفتر العمل تمارين وليس حلًا، وملف CSV هو الدليل الأصلي الذي يجب إبقاؤه دون تعديل. `requirements.txt` خاص بتشغيل هيكل API. يوفر `main.py` و`routes.py` اتصال HTTP، ويحدد `schemas.py` العقد العام، بينما يحتوي `internal.py` على أمثلة داخلية قابلة للاستبدال.

المواقع المقترحة: `repository.py` للوصول إلى التخزين، و`agent.py` للنموذج والوكيل، و`tools.py` للأدوات، و`validation.py` لقواعد التطبيق، و`workflow.py` لنقطة تنفيذ البحث. يحتوي `infrastructure/` على الإعدادات والأخطاء والتتبع وأدوات الملفات الاختيارية. هذه مسؤوليات مقترحة وليست ترتيب تنفيذ إلزاميًا.

## ما الذي يعمل قبل إكمال التمرين؟

شغّل الخادم والواجهة باتباع أدلتهما. يعيد `/health` الرمز 200، ويعيد `/ready` الرمز 503 لأن فحوص جاهزية التخزين والتطبيق غير منفذة. تعيد طلبات البحث والتفاصيل الصحيحة 503 مع `FURSAH_NOT_IMPLEMENTED`، والطلبات غير الصالحة 422. هذه حالات مقصودة في البداية وليست خلل تثبيت.

## وقت التقييم

وقت الصف هو **18 أكتوبر 2026 الساعة 12 ظهرًا بتوقيت الرياض**. اضبطه في بيئة الخادم باتباع [سياسة الوقت](backend/README.ar.md#evaluation-time) لتطابق تمرين الدفتر. خارج التمرين، يظل وقت الطلب الفعلي هو الافتراضي. لا تعدّل تواريخ المصادر.

## متى يكون التمرين مكتملًا؟

- جهز كامل البيانات الخام بأسلوب قابل لإعادة التشغيل وبالتخزين الذي اخترته.
- اربط تنفيذك بعقد البحث والتفاصيل العام.
- أعد نتائج مدعومة بالمصادر أو طلب معلومات ناقصة أو عدم تطابق أو أخطاء منظمة حسب الحالة.
- احتفظ بالمصادر وعدم اليقين والتعارضات، ولا تخترع تأكيدًا للأهلية.
- اجعل الجاهزية تعكس مكوناتك وإعداداتك الفعلية.
- اعرض التطبيق من البداية للنهاية واشرح قرارات تصميمك.

استخدم أمثلة دليل الخادم و`/docs` لفهم الواجهة البرمجية. الاختبار والتقييم الشامل مخصصان لليوم اللاحق.
