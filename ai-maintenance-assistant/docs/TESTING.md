## مستويات الإثبات

- `python -m pytest -q` من backend: SQLite مؤقتة، heuristic معلن، ومتجهات مضبوطة لاختبار ضوابط RAG. لا يُعتبر إثباتًا لجودة ASL أو embeddings الحقيقية.
- `python scripts/setup_rag.py --build-only` بعد تنزيل embeddings: اختبار استرجاع فعلي بكل نموذج embeddings المحلي وحد التشابه.
- تشغيل ASL المحلي والتحقق من `/ready`: يثبت التحميل والتوليد الأولي. يحتاج اختبار بلاغات فعلية للتحقق من الاستخراج واختيار الإجراءات.
- `npm run test:e2e` من frontend: متصفح Chromium منفصل يتصل بتطبيق API فعلي على 8018 مع قاعدة مؤقتة. النموذج والمتجهات مضبوطان، وبعض حالات الرد الفاسد أو الشبكة fixtures معلنة.

اختبارات المتصفح تشمل خيارات radio الأصلية: الأسهم للأعلى والأسفل والالتفاف، Space، محطة Tab واحدة، مؤشر التركيز، الاسم المتاح، وإرسال الجهاز المحدد. لا يُعد فحص الاسم المتاح اختبارًا كاملًا بقارئ شاشة فعلي.

اختبار التباين يقيس ألوان CSS المحسوبة في المتصفح على الخلفيات العادية والمحددة وعند تمرير المؤشر، بما فيها وصف الجهاز ومعرفه وإرشادات النموذج ونص placeholder ومسار التنفيذ. الحد الأدنى للنصوص المشمولة 4.5:1، ويحفظ Playwright القياسات في المرفق `browser-contrast.json`.
- تقرير `backend/data/reports/local-stack-verification.json`، عند وجوده: تحقق قبول نهائي مع وضع التجربة والنتائج والأوقات لكل حالة.

مع backend محلي شغّال بمحرك llama.cpp، تقدر تعيد اختبار القبول الفعلي من مجلد backend:

```powershell
python scripts/verify_local_stack.py
```

هذا الاختبار يستعير خدمة ASL الموجودة بدون تشغيلها أو إيقافها، ويستخدم بيانات seed في قاعدة مؤقتة. بلاغات النموذج والبحث الفعلي منفصلة في التقرير عن حقن JSON الفاسد المقصود واختبار formatter الفارغ.

## أوامر الاختبار

```powershell
cd backend
python -m pytest -q
```

```powershell
cd frontend
npm run build
$env:BACKEND_PYTHON='C:/path/to/python.exe'
npm run test:e2e
```

حدد Python الذي يحتوي مكتبات backend. إن لم تحدده، إعداد Playwright يبحث عن backend/.venv. المنفذان 8018 و5178 لازم يكونان متاحين. لأول تشغيل، إذا Chromium غير موجود: `npx playwright install chromium`.

الاختبارات ما تستخدم app.db الخاصة بالمستخدم. مسارات `/__test__` موجودة في tests/browser_server.py فقط؛ تشغيل app.main لا يضيفها.

## تحقق يدوي

يحفظ `QA_AUDIT.md` تقرير اكتشاف الملاحظات قبل إصلاحها، و`QA_REPAIRS.md` يوثق المعالجة والتحقق اللاحق. أُدخلت الحالات المصححة في مجموعة regression الافتراضية: `tests/qa/test_adversarial_cases.py` و`frontend/qa/adversarial.spec.ts` تعملان مع الأوامر العادية أعلاه. اختبارات المتصفح تشمل الاستعادة بعد reload في سؤال أو اختيار جهاز أو نتيجة نهائية، واكتمال الطلب من تبويب آخر، وانشغال القراءة، وفقد رد الاستكمال بعد التزام التذكرة.

1. «المكيف لا يعمل» في «غرفة 999»: جهاز غير مسجل وبدون تذكرة.
2. «الطابعة تعلق الورق وما تطبع» ثم «الدور الثالث»: ثلاث خيارات، ثم اختيار 305 يحفظ PR-305-01.
3. «المكيف يهرب موية على اللوحة الكهربائية» بدون موقع: يظهر التحذير مع السؤال. متابعة B12 تصعّد التذكرة وتحفظ مرجع السلامة.
4. «المكيف يهرب موية» في B12: التوصية من إجراء التسرب وتظهر مصادرها.
5. «المكيف لا يعمل» في B12: تذكرة فحص ميداني بدون مصدر أو تعليمات إصلاح مختلقة.
6. قارن ticket_id وthread_id وasset_id وstatus والتوصية والمراجع مع SQLite. الأوقات تختلف حسب العمل الفعلي.
